## 一、本课核心：新旧语义（最容易引起异议的概念）

**"新旧" = 发送端发出的先后，与到达顺序无关。**

- **新包** = 发送端**更晚发出**的包（序号更大，回绕感知）
- **旧包** = 发送端**更早发出**的包（序号更小，回绕感知）

```
发送端发出顺序：100 → 101 → 102 → 103 → 104 → 105
网络传输：      100  101  102  ──105──  104  103     ← 103 绕路最久
接收端到达：    100  101  102  105  104  103
```

103 最后一个到，但它**在发送端最早发出**（先发 103 才发 104/105）→ **103 是旧包**。`newest_seq_num_` = 已收到包中"发送端最晚发出"的序号（此例为 105）。

**为什么用"新旧"不用"大小"**：RTP seq 是 16 位，会回绕（65535 → 0）：

```
收到：65534 → 65535 → 0 → 1 → 2
数值上 2 < 65535，但 2 明明是更新发出的包 —— 数值大小关系在回绕后反转
```

所以比较必须用回绕感知的 `webrtc::AheadOf(a, b)`（"a 是否比 b 新"，16 位模运算）：

```cpp
webrtc::AheadOf(8, 2) == 1      // 8 比 2 新（正常，数值也大）
webrtc::AheadOf(65510, 2) == 0  // 65510 比 2 旧！回绕后 2 更新
```

同理 `nack_list_` 用 `DescendingSeqNumComp` 排序（而不是 `std::less`）——map 里序号排序也要回绕安全。

## 二、OnReceivedPacket 逐段逻辑

```cpp
int NackRequester::OnReceivedPacket(uint16_t seq_num) {
    // ① 首包：初始化前沿，return 0
    if (!initialized_) { newest_seq_num_ = seq_num; initialized_ = true; return 0; }

    // ② 重复包（同一 seq 收到两次）：直接忽略
    if (seq_num == newest_seq_num_) return 0;

    // ③ 旧包分支：AheadOf(newest, seq_num) == 1
    //    可能是乱序包（绕路晚到），也可能是重传包（之前判定丢失，现在补到）
    if (webrtc::AheadOf(newest_seq_num_, seq_num)) {
        auto it = nack_list_.find(seq_num);
        int nacks = 0;
        if (it != nack_list_.end()) {
            nacks = it->second.retries;   // 记录的重传次数
            nack_list_.erase(it);         // 补齐了 → 从缺失列表移除
        }
        return nacks;   // 重传包返回 retries；纯乱序返回 0
    }

    // ④ 新包分支：前沿推进，沿途缺口记入缺失档案，触发一次 NACK 点名
    AddPacketsToNack(newest_seq_num_ + 1, seq_num);  // 缺口区间全记入 nack_list_
    newest_seq_num_ = seq_num;                       // 前沿前进

    std::vector<uint16_t> nack_batch = GetNackBatch(kSeqNumOnly);  // 首次点名
    if (!nack_batch.empty()) {
        SignalNackSend(nack_batch);                  // 经 sigslot 上报 NACK 列表
    }
    return 0;
}
```

返回值 = **该包的重传次数（times_nacked）**，流入 `Packet::times_nacked`。

### GetNackBatch 首次点名（6.1.3）

```cpp
// 首次点名: 只挑没发过 NACK 的包(send_at_time == -1), 置重传次数/时间, 超 10 次放弃
std::vector<uint16_t> NackRequester::GetNackBatch(NackFilterOptions option) {
    bool consider_seq_num = (option != kTimeOnly);
    ...
    bool can_nack_seq_num_passed = (it->second.send_at_time == -1);  // 没发过 NACK 的
    if (consider_seq_num && can_nack_seq_num_passed) {
        nack_batch.emplace_back(it->second.seq_num);  // 点名
        ++it->second.retries;                          // 重传次数 +1
        it->second.send_at_time = now;                 // 记时间, 下次不再被 kSeqNumOnly 选中
        if (it->second.retries >= kMaxNackRetries) {   // 超 10 次放弃
            nack_list_.erase(it++);
        }
    }
}
```

注意：`send_at_time` 置位后，该包在 kSeqNumOnly 里就不会再被选中——**重传靠的是 kTimeOnly（RTT 退避）分支**，kMaxNackRetries 是给那个分支备的超限放弃闸门。

### 定时触发重传（6.1.4）：kTimeOnly 分支

```cpp
// 20ms 周期定时器 → ProcessNacks → GetNackBatch(kTimeOnly)
bool can_nack_timestamp_passed = (now - it->second.send_at_time) > rtt_ms_;
//                                 └─ 距上次重传超过 RTT 才再次点名(两次重传间隔 ≥ RTT)
if ((consider_seq_num && can_nack_seq_num_passed) ||
    (consider_timestamp && can_nack_timestamp_passed)) { ... }
```

**两路触发的分工**：
| 触发 | 条件 | 作用 |
|------|------|------|
| kSeqNumOnly（新包到达时） | `send_at_time == -1`（没发过） | **首次点名**：缺口刚出现，立刻报 |
| kTimeOnly（20ms 定时器） | 距上次重传 > RTT | **重传点名**：重传包可能又丢了，RTT 后补点 |

**RTT 来源（易混淆点）**：`RTT = A - LSR - DLSR` 只能由**媒体发送方**计算（A 是它收到 RR 的时刻）；SFU 作为纯接收方收不到对端 RR 的回报，测不到 RTT → 用默认 `kDefaultRttMs = 100ms`，`UpdateRtt()` 留接口供外部喂入（标准 WebRTC 里由发送流测 RTT 后经共享 RttStats 喂给 NackModule，对称假设）。

### 过期清理（6.1.5）：缺口不是无限追

```cpp
const uint16_t kMaxPacketAge = 10000; // 过期线: 距最新序号超 10000 不再追
// AddPacketsToNack 开头:
auto it = nack_list_.lower_bound(seq_num_end - kMaxPacketAge);  // 过期线边界
nack_list_.erase(nack_list_.begin(), it);  // 清掉比过期线更旧的全部
```

语义：重传 10 次还补不到的包（超限放弃）+ 一直没来的包，档案留着会无限膨胀 → 每来新包清一次"太旧不追"的。呼应 v2_6 概述问题 3：**放弃的包靠下一关键帧兜底**。参考的等价实现是 `ClearUpTo`（FrameContinuous 驱动）。

## 三、乱序 vs 重传：同一个旧包，两种身份

旧包到达时，怎么区分它是乱序还是重传？——**查 nack_list_**：

| 旧包身份 | 是否在 nack_list_ | 处理 |
|---------|------------------|------|
| 纯乱序 | 不在（从没判定过它丢） | 返回 0，什么都不做 |
| 重传恢复 | 在（之前记过缺失） | 取 retries 次数返回 + 从列表删除 |

本质：**nack_list_ 就是"曾经判定为丢失"的档案**，在档 = 重传补到，不在档 = 只是乱序。

## 四、关键帧锚点清理（6.1.6）：超限时放弃"关键帧之前"的缺失包

**为什么放弃**：GOP 内 P 帧依赖前帧解码，任何一帧的包永久丢失 → 该帧及之后所有帧都解不出，参考链断。此时**关键帧之前**的缺失包即使重传成功也没人用（解码端在等新关键帧重启）→ 对它们发 NACK 纯浪费带宽。

**keyframe_list_：关键帧首包锚点表**（`is_keyframe` = 首包标记 && 帧类型为关键帧，即关键帧**首包**的 seq 才记锚点）

```cpp
if (is_keyframe) {
    keyframe_list_.insert(seq_num);  // 记关键帧首包锚点
}
// 锚点也按 kMaxPacketAge 清过期, 防 keyframe_list_ 无限膨胀
auto it = keyframe_list_.lower_bound(seq_num - kMaxPacketAge);
if (it != keyframe_list_.begin()) {
    keyframe_list_.erase(keyframe_list_.begin(), it);
}
```

**RemovePacketsUntilKeyFrame：触发时机 = nack_list_ 超限（kMaxNackPackets=1000）**

```cpp
// 超限清理: 删掉关键帧之前的缺失包(参考链已断, 重传也白费), 腾空间记新缺口
bool NackRequester::RemovePacketsUntilKeyFrame() {
    while (!keyframe_list_.empty()) {
        auto it = nack_list_.lower_bound(*keyframe_list_.begin()); // 第一个 >= 最旧锚点的缺失包
        if (it != nack_list_.begin()) {   // 锚点之前有缺失包 → 全清, 腾出空间
            nack_list_.erase(nack_list_.begin(), it);
            return true;
        }
        keyframe_list_.erase(keyframe_list_.begin());  // 该锚点前已无可清, 弃用换下一个
    }
    return false;
}
```

调用处：`AddPacketsToNack` 里 `nack_list_.size() + new_nack_num > kMaxNackPackets` 时循环调用，直到腾够空间或无可清理；清完还不够 → `nack_list_.clear()` + TODO 请求关键帧（全放弃，等 PLI 兜底，8.x 实现）。

**语义澄清**：不是"防止参考链断"（链断是重传失败的既定结果），是"**断了就果断放弃、把重传资源留给还能救的包**"——与 v2_6 概述问题 3（重传失败靠关键帧兜底）一脉相承，是 PLI 思想的接收端侧版本。

## 五、乱序直方图统计（6.1.7）：区分"乱序"与"真丢"

**背景**：包到达顺序 `100 101 105 102 103 104`，收到 105 时缺口 102/103/104 立刻被记档点名——但它们只是**乱序**，正在路上，NACK 白发、对端白重传。优化思路两条（参考只做了第 2 条，第 1 条在 WebRTC 原版存在）：

1. **时间等待**（可配置）：点名需满足 `now - created_time >= send_nack_delay_ms_`（默认 0 = 不等待）——用户实现已加
2. **序号等待**（直方图统计）：按历史乱序程度估计"乱序包一般迟到几个位置 N"，记档后等前沿推进 N 个序号仍缺才点名

**为什么用"包个数"不用"时间"**：包个数跟码率自适应。低码率流包稀疏（等固定时间在序号上几乎没推进）；高码率流包密集（等固定时间又拖太久）。序号维度与码率无关，效果一致。

### Histogram 内部结构（课程简化版）

```cpp
class Histogram {
    std::vector<size_t> values_;  // 样本环形缓冲: 存最近 max_num_packets 个乱序距离
    std::vector<size_t> buckets_; // 计数桶: buckets_[i] = 乱序距离 i 的样本个数
    size_t index_ = 0;            // 环形缓冲写入游标(下一个样本写入的位置)
};
```

- **values_**：固定窗口（reserve 容量）按到达顺序循环存乱序距离，满了覆盖最老的（`index_ = (index_+1) % capacity`）——始终反映"最近"的乱序水平
- **buckets_**：把窗口内容统计成直方图（下标 = 乱序距离，元素 = 出现次数）
- **Add(value)**：覆盖旧样本前先 `--buckets_[旧值]`，写入新值后 `++buckets_[新值]`——窗口滚动，统计同步增减

### InverseCdf(probability)：查表求分位数

- 正向 CDF：乱序距离 ≤ N 的样本占比 = 从桶 0 往右累加 `buckets_[i] / 样本总数`
- **InverseCdf(0.5) 反向查：返回 N，使"至少 50% 的样本乱序距离 ≤ N"**——即"半数乱序包会在 N 个序号内到齐"
- **probability 不是"乱序发生的概率"**（样本全是乱序，乱序是既成事实），是**对 N 的覆盖率要求**：0.5 = N 罩住一半乱序包（另一半乱序更远的会误 NACK，但 N 小、真丢恢复快）；0.9 = N 罩住九成（误伤少但 N 大、恢复慢）

## 七、一句话记忆

> **NackRequester 三件套：眼睛（OnReceivedPacket 新旧判断）、手（GetNackBatch 点名）、节拍器（20ms 定时器）**。链路：新包 → 前沿推进 + 缺口记档 + 首次点名（kSeqNumOnly）→ 定时重传（kTimeOnly，间隔 ≥ RTT，默认 100ms）→ 超 10 次或超 10000 个位置放弃清档。"新旧"指**发送端发出的先后**（回绕后数值大小会反转，必须用 AheadOf 回绕感知比较）；`newest_seq_num_` = 已收包中发送端最晚发出的序号（接收前沿）。nack_list_ 超限时按关键帧锚点（keyframe_list_）批量放弃"关键帧之前"的缺失包——参考链已断，重传也白费，等关键帧兜底。
