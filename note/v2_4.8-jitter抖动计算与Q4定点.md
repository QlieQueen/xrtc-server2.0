## 一、jitter 是什么

**interarrival jitter = 到达间隔抖动**，衡量**网络延迟的变化量**（不是延迟本身）。发送端每帧 3000 tick 发一个包，理想下到达也均匀；网络让到达节奏变乱，乱的程度就是 jitter。RR 上报给发送端做码率自适应/拥塞控制。

## 二、D 公式推导（核心洞察）

发送端包 i 的**发送时刻** = RTP 时间戳 `S_i`（90k tick）；接收端包 i 的**到达时刻** = 本地时钟 `R_i`（毫秒→tick）。

```
D(i,j) = (Rj − Ri) − (Sj − Si)
       = (Rj − Sj) − (Ri − Si)        // 关键变换
       = 包 j 的端到端延迟 − 包 i 的端到端延迟
```

**差值自动抵消所有固定偏移**：两端时钟不同步 Δ、固定排队、固定编码延迟——相减时全部消掉，只剩"变化的部分"。这就是 jitter 算"抖动"而非"延迟"的原因。

## 三、EWMA 平滑

```
J(i) = J(i−1) + (|D(i−1,i)| − J(i−1)) / 16
```

**当前估计 = 上次估计 + 新样本与估计之差的 1/16**。16 是平滑因子：单次异常包只把估计拽一小截，连续大抖动估计才爬升。D 是瞬时样本（过客），J 是常驻估计。

## 四、Q4 定点：为什么代码里没有"/16"

**核心困惑点：注释写 `J += (|D|−J)/16`，代码里却找不到 `/16`，只有 `<<4` 和 `>>4`。**

`jitter_q4_` 存的是 **16×J**（Q4，放大 16 倍用整数模拟小数）。把注释公式两边 ×16：

```
J(i)   = J(i−1) + (|D|−J(i−1))/16          ← 注释：J 的方程
16·J(i) = 16·J(i−1) + (|D|−J(i−1))         ← 两边×16：EWMA 的 /16 被约掉了！
```

于是代码做的是 `jitter_q4_ += (|D| − J)`（原量级差值直接加）。而"原量级差值"在 Q4 世界里 = `((|D|<<4) − jitter_q4_) >> 4`：

```cpp
jitter_q4_diff = (time_diff_samples << 4) - jitter_q4_;   // 16·(|D| − J)，放大对齐
jitter_q4_ += ((jitter_q4_diff + 8) >> 4);                // 缩回原量级 + 四舍五入
```

**两个 16 不是一回事**：

| | 值 | 含义 |
|---|---|---|
| EWMA 平滑因子 | /16 | 只取差值的 1/16 更新 J（乘 16 后被约掉） |
| Q4 定点倍数 | ×16 | 整数模拟小数的放大 |

`+8` 是 0.5×16 的舍入偏置：`(x+8)>>4` = `round(x/16)`，不加会系统性偏小。J 真实值 = `jitter_q4_ >> 4`。

**变量语义随时间漂移**：本轮开头 `jitter_q4_` = `16·J(i−1)`（上一轮估计），更新完 = `16·J(i)`；下一轮又退化扮演 `J(i−1)`。对注释找符号要看"进入本轮那一刻"。

## 五、450000 阈值 = 5 秒防污染

`450000 = 5秒 × 90000Hz`。网络停顿 >5 秒是异常事件（断网/切换），D 会算出 45 万量级的假抖动，喂进滤波污染估计，直接砍掉。工程实用主义，非数学推导。

## 六、触发条件

```cpp
if (packet.Timestamp() != last_received_timestamp_ &&
    (transmitted.packets - retransmitted.packets) > 1)
```

- `Timestamp != last`：**同帧切片共享同一时间戳**，它们之间的 D 是切片/突发传输不是抖动 → 跳过。**I 帧几十个切片只贡献一个采样点**（新帧首片 vs 上帧末片），采的是"帧间节奏"。
- `packets > 1`：首包没有上一个值，避免假巨抖动。

## 七、联调踩坑：毫秒 vs tick 单位混淆（重要）

自己手写时把触发条件写成了：

```cpp
if (packet.Timestamp() != last_received_time_ms_ && ...)   // ✗ 拿 tick 比毫秒
```

- `packet.Timestamp()`：RTP 时间戳，**tick**（3000 的倍数）
- `last_received_time_ms_`：上一包**到达时刻，毫秒**（1234567 这种数）

两单位不同、量级不同，`!=` 恒真 → **同帧切片也进 jitter**，`Sj−Si=0` 的假样本混入把估计拉低。

**教训：统计里凡涉及时间的比较，先问自己是哪个时间（到达时间/时间戳）、什么单位（ms/tick）。**

## 八、编码器侧 timestamp 来源（串起客户端）

客户端编码器 `frame.timestamp()` → `encoded_image_.SetTimestamp()` → RtpFragmentize 切包 → **每个 RTP 包的 header.timestamp = encoded_image_.timestamp()（同帧切片共享）** → SFU 端 `packet.Timestamp()`。这就是 D 公式的 S 侧；毫秒维度（客户端 `frame.render_time_ms()` → `capture_time_ms_`）是墙钟，对应 SFU 的 `now_ms`，不参与 jitter。

## 九、联调验证结果（云机）

```
ssrc: 1476579460, jitter: 171, D: 0
ssrc: 1476579460, jitter: 172, D: 180
ssrc: 1476579460, jitter: 178, D: 270
... jitter 稳定在 170~270，D 在 0~720 剧烈波动 ...
```

三组证据：
1. **数值合理**：270 tick ÷ 90k ≈ 3ms，云机-客户端抖动量级正常
2. **平滑可见**：单次 D=720 只把 jitter 从 202 拽到 217（+15 ≈ 720/16），EWMA 生效
3. **帧率节奏**：日志间隔 ≈ 28~33ms = 30fps，同帧跳过生效，每帧只打一条
