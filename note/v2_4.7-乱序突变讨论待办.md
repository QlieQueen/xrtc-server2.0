## 待解答:为什么 `received_seq_max_ = sequence_number - 2;`

位置: `src/modules/rtp_rtcp/receive_stat.cpp` UpdateOutOfOrder,突变确认分支(第 62 行)。

```cpp
if (received_seq_out_of_order_) {
    uint16_t expected_seq_num = *received_seq_out_of_order_ + 1;
    received_seq_out_of_order_ = absl::nullopt;
    if (packet.SequenceNumber() == expected_seq_num) { // 认定发生序列号突变,重置计数状态
        received_seq_max_ = sequence_number - 2;
        return false;
    }
}
```

触发路径:
1. 某包与前沿差 > 450 → 怀疑突变,记 `received_seq_out_of_order_ = 该包seq`, `++cumulative_loss_`, return true(不更新前沿)
2. 下一包 seq == 记录值+1 → 确认突变,把前沿设成 `sequence_number - 2`

疑点:
- 为什么是 -2 而不是 -1?第二包(确认包)到达时,顺序路径会补记 `cumulative_loss_ += (sequence_number - received_seq_max_)`(第 43 行),-2 与这个补差、以及第一包那笔 `++cumulative_loss_`,三者凑出来的账本才对平?
- 突变确认后,第一包(触发包)在账本里是"丢失"还是"收到"?

## 背景(已确认)

- 账本模型: 每包到货先 -1;顺序新包补差 +(seq - max);乱序包 return 短路只撤销自己那笔
