## 一、阶段定位

v2_3 整个阶段就是一件事：**把 RTP/RTCP 处理模块做出来**——RTCP 的发送链路 + 接收链路，两条对称的通路。

## 三、阶段完成时的能力边界

**发送侧（已闭合）**：
- 定时器周期触发 → `SendRTCP` → 复合包计算 → builders 逐个追加 → `PacketSender` 超 MTU 自动分包 → 回调发出（当前回调只打日志）

**接收侧（骨架闭合，内容待填）**：
- 复合包逐块拆解：校验（版本=2 / 长度对齐 / padding 合法）→ 首块非法整体丢弃、中间块非法计数跳过
- 按 `rtcp_block.type()` 分派 SR(200)/RR(201)，未知类型计数跳过

## 四、遗留事项（后续课程对应的坑）

1. **`HandleSr`/`HandleRr` 是空实现**——下阶段填充：SR 的 RTP↔NTP 时间线、RR 的接收统计 → NACK 决策依据
2. **`IncomingRtcpPacket` 无调用方**——还没接入媒体接收路径（SRTP 解密后）
3. **发送侧 `BuildSR`/`BuildNack`/`BuildPli` 未注册**——等 8.x/9.x 课逐个注册
4. **NACK/RTX/RTP Cache 只完成了设计**——落地在 8.x（is_pli 配置链 + BuildPli）及之后
