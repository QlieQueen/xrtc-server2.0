## 二、当前 2.0 与课程的关系

```
当前 xrtc-server2.0（1V1，DTLS-SRTP）
   = xrtcserver_v2 基线（课程起点） + 我们修的 6 个 bug
   缺：课程 2.x~6.x 的模块（rtcp_sender/receiver、video receive、rtp_rtcp_impl、mode 信令…）
```

→ 8.x 的 PLI、9.x 的 SR 都依赖课程 3.x 的 `RTCPSender`，当前 2.0 没有该模块，**不能直接从 7.3 开跳**，需先补 RTCP 基础。

## 三、学习路线（推荐：聚焦 1V多 主干）

### Phase 0 — 基线差距分析（不写代码）
- `diff` 当前 2.0 vs `xrtcserver_v2_7.3`，列出缺失/需移植的模块清单
- 交付：差距清单，确定每个 Phase 的移植范围

### Phase 1 — RTCP 发送模块（课程 3.2 ~ 3.8）
- RTCPSender：RtcpMode(kOff/kCompound/kReducedSize)、report_flags_ 标志集、
  PrepareReport(SR/RR 选择)、builders_ 函数表分派、PacketSender 序列化、
  EventLoop 周期定时上报
- 目的：8.3 PLI、9.5 SR 都复用该模块
- 交付：`src/modules/rtp_rtcp/` 补全 rtcp_sender

### Phase 2 — 双模式架构（7.3）
- 信令 `mode` 字段（transparent/live）贯通到媒体层
- transparent = 原样转发；live = 走媒体处理（1V多 走 live）
- 交付：mode 参数全链路

### Phase 3 — 多拉流管理（7.4 ~ 7.6）
- `multi_pull_streams_`：`unordered_map<stream_name, unordered_map<uid, PullStream*>>`
- AddPullStreamM / RemovePullStreamM / FindPullStreamM
- CreatePullStream / SetAnswer / StopPull 按 mode 分支（1V1 老路径保留）
- 交付：同一 stream 多个 pull 共存，互不顶替

### Phase 4 — RTP 广播分发（7.7 ~ 7.8）
- RTP 上报链：接收器 OnRtpPacket → PeerConnection::SignalRtpPacket → PushStream → manager
- live 模式 OnRtpPacket 把 push 流 RTP 广播给该 stream 名下**所有** pull
- 交付：**一推多拉画面全通**（关键里程碑，可联调验证）

### Phase 5 — PLI 关键帧请求（8.2 ~ 8.3）
- is_pli 配置链 + request_pli_interval_ms 定时器（周期发 RTCP PLI）
- BuildPli 报文（rtcp::Pli，sender/media ssrc）
- 交付：新拉流端加入 1~2s 内出关键帧

### Phase 6 — 下行发送链路 + SR 时间线（9.1 ~ 9.9，重点 9.3/9.6/9.8/9.9）
- RtpSender 发送统计（RTP/RTX 分流计数，为 SR 提供 packets/octets）
- PullStream::SendPacket → SendRtp + UpdateRtpStat（每路 pull 成完整发送端）
- RTCPReceiver 采集上游 SR（RTP↔NTP 映射）
- 9.9 SR 时间线透传：manager 广播上游 SR → 各 pull 下行 SR 复用同一时间线
- 交付：**1V多 完整版**（每路下行带 SR，多路音视频同步）

## 四、选学（与转发关系小，按需）
- 2.x 去 DTLS：如需 transparent 明文模式
- 4.x 接收统计 / 5.x 组帧 / 6.x NACK-RTX：接收侧 QoS 深水区，1V多 转发不依赖

## 五、每 Phase 标准流程（沿用 CLAUDE.md 教学法）
```
1. Grill 三问（背景知识？手写 or 指导？关注点？）
2. 看参考课程对应目录的 diff（对比相邻目录）
3. 在当前 2.0 移植代码
4. 编译（bash build.sh）+ 云机部署 + 客户端联调
5. git commit
```

## 六、验证方式（1V多）
- 一个推流端 + **两个拉流端**同时观看
- 新拉流端加入：验证 PLI 快速出画
- 停止任一拉流端：不影响其他拉流端
- 云机日志确认：多路 pull 各自 ICE 连接、RTP 转发、SR 上报
