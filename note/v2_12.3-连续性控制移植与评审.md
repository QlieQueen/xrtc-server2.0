## 二、ProcessVideoPacket 状态机

```
1. CacheVideoPacket 先缓存（10.x 的 2048 槽缓存照旧，供下行 NACK 重传命中）
2. 首包（first_seq_time_ == -1）→ video_seq_ = seq，立即广播
3. 重复/落后（AheadOrAt(video_seq_, seq)）→ 丢弃（含 RTX 二次到达、乱序先到的重复）
4. 缺口（seq != video_seq_ + 1）→ 只缓存、压住不转（等补齐）
5. 有序 → 从该 seq 起向后扫缓存，连续转发到断档（上限 kVideoPacketCacheSize=2048），
   video_seq_ = 最后转发那包
```

16 位 seq 比较全部用 `AheadOf/AheadOrAt`（回绕感知），不能写成 `seq < video_seq_`。

## 五、为什么必须和 v12.4 一起联调

v12.3 让"缺口补齐前不转发"。弱网下上行真丢包（RTX 也救不回）时，缺口**永远**补不上 → 转发永久卡死、下行停摆——这是设计内行为，兜底机制（完整 IDR 帧重启 + 清旧缓存）在 v12.4。所以：

- 正常网络联调：v12.3 单独可测（无丢包，行为与之前一致，只是多了排序）
- 弱网联调：必须 v12.4 一起上，否则拉流端在丢包场景下卡死
