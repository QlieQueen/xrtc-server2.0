### 2. GetOrCreateStat 登记 all_ssrcs_（receive_stat.cpp:145-148）

```cpp
if (nullptr == stat) {
    stat = std::make_unique<StreamStat>(ssrc, clock_);
    all_ssrcs_.push_back(ssrc);      // ← 本课新增：记录 ssrc 的稳定索引
}
```
为什么不能直接遍历 stats_（flat_map）轮询？
- flat_map = 连续内存 vector，**插入会搬移元素、使迭代器/索引失效**；轮询需要"上次位置"这个游标跨周期存活
- all_ssrcs_ 只在建桶时 append（一次），游标永远有效
- 场景：一连接 media + rtx 两个 ssrc 到齐时机不同，后者晚到也不影响轮询

### 3. RtcpReportBlocks：多 SSRC 公平轮询（receive_stat.cpp:163-172）

```cpp
std::vector<webrtc::rtcp::ReportBlock> ReceiveStat::RtcpReportBlocks(size_t max_blocks) {
    std::vector<webrtc::rtcp::ReportBlock> result;
    result.reserve(std::min(max_blocks, all_ssrcs_.size()));

    size_t ssrc_idx = 0;
    for (size_t i = 0; i < all_ssrcs_.size() && result.size() < max_blocks; ++i) {
        ssrc_idx = (last_returned_ssrc_idx_ + 1 + i) % all_ssrcs_.size();   // 上次位置+1 起步
        uint32_t media_ssrc = all_ssrcs_[ssrc_idx];
        auto stat_iter = stats_.find(media_ssrc);
        stat_iter->second->MaybeAppendReportBlockAndReset(result);
    }
    last_returned_ssrc_idx_ = ssrc_idx;
    return result;
}
```
- 为什么轮询：一个 RTCP RR 包 Report Block Count 是 5bit → **最多 31 块**（`RTCP_MAX_REPORT_BLOCKS`）。SSRC > 31 时一个包装不下，轮流上报保证公平（不会饿死后面的 ssrc）
- 环形游标：`last_returned_ssrc_idx_ + 1 + i` 从上次停下的下一个开始，包与包之间 ssrc 均匀分布
- 游标更新在循环外（i 溢出后 ssrc_idx 停在最后处理的位置）
- 注意：实际一个 RTCP 包里 31 块是上限，多 SSRC 时 m=31 包还会按字节数再截断（后续课程）


## 四、线程模型（简化版的关键）

- RtpRtcpImpl 的定时器建在 el_（RtcWorker 的 event loop）上；RTP 收包也在同一 worker 线程处理 → **收包与 RTCP 上报同线程，无锁安全**
- 真实 WebRTC：receive_statistics 有 lock_ 保护（packet router 与 RTCP 周期可能不同线程）——面试可答"本课程实现单线程串行，WebRTC 有锁"
